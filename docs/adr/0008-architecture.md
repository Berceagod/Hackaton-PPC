# ADR-0008: Core architecture
Status: accepted (updated for the Python stack)
Decision: Stateless FastAPI instances. Services: nginx, backend (+ per-category worker processes), postgres-meta (files_metadata, meter_readings, audit_logs, policies_config, upload state), postgres-blob (DB storage backend, separate instance), minio (S3), ftp, rabbitmq, later prometheus, grafana, loki, alertmanager, toxiproxy. Storage adapters in `backend/storage/` (postgres_storage.py, s3_storage.py, ftp_storage.py) behind one interface. Four RabbitMQ queues (q.meter_readings, q.outage_records, q.connection_docs, q.drone_videos) with dedicated workers, exponential-backoff retry and a dead-letter queue; messages are persistent and published with confirms, so a confirmed file survives a storage outage. Circuit breaker per storage. Streaming everywhere (64 KB reads, 5 MB chunks, S3 multipart); no whole-file buffering. Tables created at startup with CREATE TABLE IF NOT EXISTS.
Consequences: Horizontal scale via `--scale backend=N`; shared state lives in Postgres and RabbitMQ. Large-body handling vs the broker is an open point tracked in progress.md.
